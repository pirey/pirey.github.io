Fast like Neovim, pretty like VS Code, ergonomic and customizable like Neovim. That's what I want from an editor, and Zed gets close enough that I have a hard time finding a reason not to use it.

I've spent a lot of time tweaking Vim and Neovim. I like being able to shape my editor around the way I work, especially when it comes to navigation and keymaps. But I also like a good graphical interface. I want both.

Zed makes that combination feel natural. It feels fast, looks good, and lets me keep the keyboard habits that make editing comfortable.

## Fast and pretty

Speed is something I notice throughout the day. Opening files, jumping around, switching between things. None of those actions should feel like a pause in my work.

Zed feels fast in the same way Neovim does to me. I'm talking about how it feels during everyday editing, rather than a benchmark. It responds quickly enough that I don't think about the editor while using it.

At the same time, it has the visual polish I enjoy in VS Code and other IDEs. A comfortable interface matters when I'm going to stare at it for hours.

## Ergonomic and customizable

One of the reasons I keep coming back to Neovim is ergonomics. Once navigation and editing become muscle memory, it's hard to give that up.

With Vim mode and customizable keymaps, Zed gives me room to bring those habits along. I can adjust the editor to how I work, which is a big part of what I enjoy about Neovim in the first place.

## Multiple projects, with their own tasks

I often need to work on more than one project. A frontend here, a backend there, each with its own commands and terminal sessions.

Being able to work across projects with terminal tasks scoped to each project is a big deal for me. The commands belong to the project they run in, and I can keep the relevant terminals close to the code.

It sounds like a small thing, but it makes switching between projects more comfortable.

## AI agents in the editor

The AI agent feature is another reason to use Zed. Having an agent available where I'm already reading and editing code fits naturally into my workflow.

I also like the integration with third-party agents such as Codex and OpenCode. I want to choose the agent that works for me and use it from the editor.

## A couple of things I still need

There are still two Git features missing from the workflow I want in Zed.

The first is a way to review changes against a base branch. When reviewing a merge request, I want to browse the full diff between the branch and its base, move through the changed files, and read the changes in context.

The second is searching Git history for occurrences of a string, like `git log -S`, also known as pickaxe. Sometimes I need to find when a piece of code was introduced or removed. Searching the current files doesn't answer that question; I need to search the history.

I can use Git in a terminal for those workflows, but I'd like to have them available in the editor too.

Those gaps matter to me, but the rest of the experience is already compelling. Zed brings together the speed, appearance, ergonomics, project workflows, and agent integration I want. That's enough reason for me to keep using it.
